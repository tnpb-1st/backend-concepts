# Blog API

A RESTful blogging API built with Spring Boot. It supports creating, reading, updating, deleting and searching blog posts, stored in an in-memory H2 database.

## Tech stack

- Java 21
- Spring Boot 4.1.2 (Spring Web MVC, Spring Data JPA, Hibernate)
- H2 (in-memory database, with the H2 console enabled)
- Maven (via the included wrapper, pinned to 3.9.9)
- JUnit 5, Mockito and MockMvc for tests

## Running the project

```bash
./mvnw spring-boot:run
```

The API starts on `http://127.0.0.1:8080`. It is bound to loopback only, so it is not reachable from other machines.

Run the tests with:

```bash
./mvnw test
```

## H2 console

Available at `http://127.0.0.1:8080/h2-console` while the app runs.

| Field | Value |
|---|---|
| JDBC URL | `jdbc:h2:mem:blogapi` |
| User | `sa` |
| Password | see `src/main/resources/application.yaml` |

The database is in memory, so all data is lost when the app stops. Hibernate creates the schema at startup (`ddl-auto: update`).

## Data model

A post (table `tb_post`) has these fields:

| Field | Type | Notes |
|---|---|---|
| `id` | integer | Generated by the database |
| `title` | string | Required, not blank |
| `content` | string | Required, not blank |
| `category` | enum | Required. One of `Technology`, `Personal`, `Computer`, `Travel`, `Business` |
| `tags` | list of strings | Required, at least one |
| `publishedAt` | datetime | Set by the server |
| `updatedAt` | datetime | Set by the server |

## Endpoints

Base path: `/posts`

| Method | Path | Description | Success | Errors |
|---|---|---|---|---|
| `GET` | `/posts` | List all posts | 200 | |
| `GET` | `/posts/search?term=java` | Posts whose title, content or category contains the term (case-insensitive) | 200 | 400 if `term` is missing |
| `GET` | `/posts/{id}` | Get one post | 200 | 404 |
| `POST` | `/posts` | Create a post | 201 | 400 |
| `PUT` | `/posts/{id}` | Update a post | 201 | 400, 404 |
| `DELETE` | `/posts/{id}` | Delete a post | 204 | 404 |

### Example

```bash
curl -i -X POST http://127.0.0.1:8080/posts \
  -H "Content-Type: application/json" \
  -d '{"title": "Hello", "content": "My first post", "category": "Technology", "tags": ["intro", "java"]}'
```

```json
{
  "id": 1,
  "title": "Hello",
  "content": "My first post",
  "category": "Technology",
  "tags": ["intro", "java"],
  "publishedAt": "2026-11-04T10:00:00.000000",
  "updatedAt": "2026-11-04T10:00:00.000000"
}
```

### Error responses

A post that does not exist returns 404:

```json
{ "message": "Post with id 99 not found" }
```

A post that fails validation returns 400 and names the offending field:

```json
{ "field": "title", "message": "Post title must not be empty" }
```

## Project structure

```
src/main/java/github/io/tnpb_1st/blogapi
├── BlogapiApplication.java      Application entry point
├── controller/PostController    HTTP endpoints; turns exceptions into status codes and bodies
├── service/PostService          Business logic and post validation
├── repository/PostRepository    Spring Data JPA repository, including the JPQL search query
├── entity/                      Post entity and Category enum
└── exception/                   PostNotFoundException, PostValidationException
```

## Tests

- `PostControllerTest`: `@WebMvcTest` with a mocked service. Checks the status codes and response bodies of every endpoint.
- `PostRepositoryTest`: `@DataJpaTest` against H2. Checks the search query (title, content and category matches, case-insensitivity).
- `BlogapiApplicationTests`: checks that the application context loads.
